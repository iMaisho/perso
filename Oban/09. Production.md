# Préparation pour la production

## Objectifs

Dans les exercices précédents nous avons travaillé dans un environnement de développement avec peu de volume de données.

En production, plusieurs nouveaux problèmes apparaissent :

- accumulation de jobs dans la base
- jobs bloqués après crash du système
- besoin de monitoring et d'observabilité

Dans ce chapitre nous allons voir :

- la **gestion du cycle de vie des jobs**
- la **récupération des jobs orphelins**
- l'**instrumentation avec Telemetry**
- la **surveillance du système en production**

## 1. Gestion des jobs avec le plugin Pruner

### Problème

Oban stocke les jobs dans la table `oban_jobs`. Ilsrestent en base après leur exécution pour permettre l'introspection, l'unicité des jobs et l'historique, mais cela peut finir par poser problème car la table grossit indéfiniment

### Solution : le plugin Pruner

Le plugin **Pruner** supprime automatiquement les jobs completed, cancelled et discarded après une certaine durée.

Pour conserver les jobs **7 jours** :

```elixir
plugins = [
  {Oban.Plugins.Pruner, max_age: 60 * 60 * 24 * 7}
]

Oban.Config.validate(plugins: plugins)
```

## 2. Gestion des jobs orphelins avec Lifeline

### Problème

Lorsqu'un serveur s'arrête brutalement, certains jobs peuvent rester dans l'état `executing`. On les appelle job orphelins. Ce n'est pas grave, car ils ont été persistés, mais il faut s'en occuper.

Deux mécanismes existent :

Le paramètre `shutdown_grace_period` donne plus de temps au système pour terminer les jobs avant l'arrêt.

### Plugin Lifeline

Le plugin **Lifeline** permet de remettre les jobs bloqués en état available afin qu'ils puissent être relancés.

### Configuration

Pour récupérer les jobs après **5 minutes** :

```elixir
plugins = [
  {Oban.Plugins.Lifeline, rescue_after: :timer.minutes(5)}
]

Oban.Config.validate(plugins: plugins)
```

## 3 — Monitoring avec Telemetry

Oban utilise **Telemetry** pour générer des événements sur :

- le démarrage d'un job
- la fin d'un job
- les erreurs
- les requêtes base de données

Le moyen le plus simple d'utiliser Telemetry est d'activer le logger fourni par Oban.

```elixir
Oban.Telemetry.attach_default_logger(encode: false)
```

# 9 — Test du logging

Nous allons tester les logs générés lors de l'exécution de jobs.

## Worker de test

```elixir
defmodule FakeWorker do
  use Oban.Worker

  def perform(%{args: %{"action" => "ok"}}), do: :ok
  def perform(%{args: %{"action" => "error"}}), do: {:error, :boom}
end
```

---

## Test complet

```elixir
ExUnit.start(auto_run: false)

defmodule ChowMojo.TelemetryLoggingTest do
  use ChowMojo.ObanCase

  import ExUnit.CaptureLog

  setup do
    Logger.configure(level: :debug)
  end

  defmodule FakeWorker do
    use Oban.Worker

    def perform(%{args: %{"action" => "ok"}}), do: :ok
    def perform(%{args: %{"action" => "error"}}), do: {:error, :boom}
  end

  test "logging events triggered by execution jobs" do
    Oban.Telemetry.attach_default_logger(encode: false)

    logged =
      capture_log(fn ->
        perform_job(FakeWorker, %{action: "ok"})
        perform_job(FakeWorker, %{action: "error"})
      end)

    assert logged =~ "job:start"
    assert logged =~ "job:stop"
    assert logged =~ "job:exception"
  end
end

ExUnit.run()
```

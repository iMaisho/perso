# Guide essentiel : Background Jobs avec Oban (Elixir)

https://hexdocs.pm/oban/Oban.html

Ce guide explique comment utiliser **Oban** pour exécuter des tâches en arrière-plan dans une application Elixir.

Cas étudié : envoyer un **email de bienvenue** après la création d’un utilisateur.

## 1. Architecture simplifiée

```

User signup
↓
Insert user in database
↓
Create Oban job
↓
Queue
↓
Worker
↓
Execute background logic
```

## 2. Création d’un Worker Oban

Un **worker** est un module qui exécute un job.

Exemple : envoyer un email de bienvenue.

```elixir
defmodule MyApp.WelcomeWorker do
  use Oban.Worker, queue: :email

  @impl Oban.Worker
  def perform(%Oban.Job{args: %{"id" => id}}) do
    id
    |> MyApp.get_user()
    |> MyApp.send_welcome_email()
  end
end
```

### Points importants

#### 1. La queue

```elixir
queue: :email
```

Le job sera exécuté dans la queue `email`.

Les queues permettent :

- d’organiser les jobs
- de limiter la concurrence


#### 2. Les arguments

Les arguments sont **toujours sérialisés en JSON**.

Donc :

❌ mauvais :

```
%{user: user_struct}
```

✅ correct :

```
%{id: user.id}
```

Ensuite le worker récupère les données depuis la base.


# 3. Ajouter un job après un événement

Après la création d’un utilisateur, on instancie un worker pour créer un job, et on utilise `Oban.insert!` pour le persister.

```elixir
def create_user(params) do
  changeset = MyApp.User.insert_changeset(params)

  with {:ok, user} <- MyApp.Repo.insert(changeset) do
    %{id: user.id}
    |> MyApp.WelcomeWorker.new()
    |> Oban.insert!()

    {:ok, user}
  end
end
```


Le job est alors enregistré dans la base et exécuté par Oban


# 4. Bonnes pratiques

✔ passer **uniquement des IDs dans les jobs**
✔ récupérer les données dans le worker
✔ organiser les jobs avec des queues
✔ tester avec `inline` et `manual`

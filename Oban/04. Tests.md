# Tester les jobs avec Oban

https://hexdocs.pm/oban/Oban.html

Oban propose deux modes de test.

## Mode 1 : `:inline`

Les jobs sont exécutés **immédiatement dans le test**.

### Setup

```elixir
setup do
  start_supervised!({Oban, repo: MyApp.Repo, testing: :inline})

  :ok = Ecto.Adapters.SQL.Sandbox.checkout(MyApp.Repo)
end
```

### Test

```elixir
test "creating a user delivers a welcome email" do
  params = %{email: "shannon@sorentwo.com", name: "Shannon"}

  {:ok, user} = MyApp.Users.create_user(params)

  assert_email_delivered(user.email)
end
```

### Vérification

```elixir
defp assert_email_delivered(email) do
  assert_receive {:delivered, ^email}, 250
end
```

Le worker est exécuté immédiatement.

## Mode 2 : `:manual`

Dans ce mode :

- les jobs sont **stockés en base**
- ils **ne sont pas exécutés automatiquement**

Cela permet de vérifier que le job a bien été ajouté avec les bons arguments.

### Setup

```elixir
setup do
  start_supervised!({Oban, repo: MyApp.Repo, testing: :manual})

  :ok = Ecto.Adapters.SQL.Sandbox.checkout(MyApp.Repo)
end
```

### Activer les helpers de test

Ajouter :

```elixir
use Oban.Testing, repo: MyApp.Repo
```

### Test

```elixir
test "creating a user enqueues a welcome email" do
  params = %{email: "shannon@sorentwo.com", name: "Shannon"}

  {:ok, user} = MyApp.Users.create_user(params)

  assert_enqueued(
    worker: MyApp.WelcomeWorker,
    queue: :email,
    args: %{id: user.id}
  )
end
```

On vérifie :

- le worker
- la queue
- les arguments

# 7. Différence entre les modes de test

| Mode   | Comportement                         |
| ------ | ------------------------------------ |
| inline | exécute les jobs immédiatement       |
| manual | vérifie seulement l’insertion du job |

En pratique il faut combiner les deux types de tests, :inline pour tester la logique, et manual pour tester l'insertion en base et l'enqueue

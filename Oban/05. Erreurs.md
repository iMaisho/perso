# Gestion des erreurs dans un Worker Oban

https://hexdocs.pm/oban/Oban.html

## 1. Cas normal : notification réussie

Le worker récupère une commande puis tente de notifier le restaurant.  
Si tout fonctionne, il retourne `:ok`.

```elixir
def perform(%Job{args: %{"id" => order_id}}) do
  order_id
  |> MyApp.get_order()
  |> MyApp.notify_restaurant()
  |> case do
    :ok ->
      :ok
  end
end
```

### Test associé

On vérifie que le worker retourne bien `:ok` lorsque tout se passe correctement.

```elixir
defmodule MyApp.NotifierSuccessTest do
  use MyApp.ObanCase

  test "successfully notifying the restaurant about an order" do
    order = insert(:order, :success)

    assert :ok =
      perform_job(MyApp.RestaurantNotifier, %{id: order.id})
  end
end
```

## 2. Cas d’erreur serveur (HTTP 503)

Une requête externe peut échouer avec une erreur serveur.
Dans ce cas, on retourne `{:error, reason}` pour indiquer à Oban que le job doit être **réessayé plus tard**.


```elixir
def perform(%Job{args: %{"id" => order_id}}) do
  order_id
  |> MyApp.get_order()
  |> MyApp.notify_restaurant()
  |> case do
    :ok ->
      :ok

    {:error, status, body} ->
      {:error, {status, body}}
  end
end
```

## Test associé

On vérifie que le worker retourne bien une erreur.

```elixir
defmodule MyApp.NotifierFailureTest do
  use MyApp.ObanCase

  test "encountering an unexpected error during notification" do
    order = insert(:order, :failure)

    assert {:error, {503, _}} =
      perform_job(MyApp.RestaurantNotifier, %{id: order.id})
  end
end
```


## 3. Cas de limitation de requêtes (HTTP 429)

Certaines API imposent des **limites de requêtes**.
Lorsqu’une erreur `429 Too Many Requests` survient, on peut **attendre avant de réessayer**.

Pour cela, Oban permet de retourner : `{:snooze, seconds}`

```elixir
def perform(%Job{args: %{"id" => order_id}}) do
  order_id
  |> MyApp.get_order()
  |> MyApp.notify_restaurant()
  |> case do
    :ok ->
      :ok

    {:error, 429, _} ->
      {:snooze, 10}

    {:error, status, body} ->
      {:error, {status, body}}
  end
end
```

Ici, le job sera **reprogrammé dans 10 secondes**.

## Test associé

```elixir
defmodule MyApp.NotifierRateLimitedTest do
  use MyApp.ObanCase

  test "snoozing when order notification is rate limited" do
    order = insert(:order, :rate_limited)

    assert {:snooze, 10} =
      perform_job(MyApp.RestaurantNotifier, %{id: order.id})
  end
end
```

# 4. Cas d’annulation du job

Il peut arriver que la commande ait **déjà été envoyée au client**.
Dans ce cas, notifier le restaurant n’a plus de sens.

On doit donc **annuler définitivement le job**.

Pour cela, Oban propose : `{:cancel, reason}`

```elixir
def perform(%Job{args: %{"id" => order_id}}) do
  order_id
  |> MyApp.get_order()
  |> MyApp.notify_restaurant()
  |> case do
    :ok ->
      :ok

    {:error, 429, _} ->
      {:snooze, 10}

    {:error, status, body} ->
      {:error, {status, body}}

    {:cancel, reason} ->
      {:cancel, reason}
  end
end
```

## Test associé

```elixir
defmodule MyApp.NotifierCancelTest do
  use MyApp.ObanCase

  test "cancel when order already dispatched" do
    order = insert(:order, :already_dispatched)

    assert {:cancel, "already dispatched"} =
      perform_job(MyApp.RestaurantNotifier, %{id: order.id})
  end
end
```

# Résumé des retours possibles d’un worker Oban

| Retour               | Signification                    |
| -------------------- | -------------------------------- |
| `:ok`                | Le job a réussi                  |
| `{:error, reason}`   | Le job a échoué et sera réessayé |
| `{:snooze, seconds}` | Le job est reporté               |
| `{:cancel, reason}`  | Le job est annulé définitivement |


# Points clés à retenir

* `perform_job/2` permet de **tester un worker directement**.
* Chaque type d’erreur doit être **géré explicitement dans le worker**.
* Oban offre plusieurs stratégies :

  * retry (`{:error, ...}`)
  * délai (`{:snooze, ...}`)
  * annulation (`{:cancel, ...}`)

Ces mécanismes permettent de construire des **jobs robustes face aux erreurs externes**.

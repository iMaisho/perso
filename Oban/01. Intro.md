# Oban : Introduction

https://hexdocs.pm/oban/Oban.html

## Qu'est ce que c'est ?

Oban est un système qui permet d’exécuter des tâches en arrière-plan (background jobs) dans une application Elixir.

Concrètement on peut lancer des tâches asynchrones, sans bloquer l'application.

- envoyer un email
- traiter un fichier
- appeler une API externe
- générer un rapport
- envoyer des notifications

C'est pratique pour les tâches lentes,coûteuses en ressources ou susceptibles d’échouer, on les exécute en dehors du flux principal de l’application.

## Pourquoi l'utiliser ?

Elixir possède déjà `Task.async` et `Task.Supervisor` pour effectuer des tâches asynchrones, donc pourquoi on aurait besoin d'une dépendence supplémentaire ?

Parce que la plupart des systèmes de gestion de jobs sont **éphémères**, on les lance sur un thread, ils exécutent la tâche, et ils suppriment les données.

Oban utilise une approche différente basée sur la persistance. Chacun des jobs sont écrits dans une base de donnée dédiée, ce qui permet tout un tas de chose :

- Un job qui s'exécute alors que le serveur redémarre n'est pas perdu
- Un job qui échoue est toujours stocké en base avec un état, ce qui permet de réessayer
- Un job peut être mis en attente pour être lancé plus tard

## Concepts clés

### Node

Un node est une instance de la VM Beam, donc en gros un serveur sur lequel l'application est déployé.

Plusieurs nodes peuvent partager la même base PostrgreSQL pour traiter les jobs, donc Oban peut fonctionner sur plusieurs serveurs en parallèle

### Instance

Une instance Oban est un superviseur dans l'application. On peut avoir plusieurs instances en simultané, à condition qu'elles aient des noms uniques.

### Queue

Les jobs sont organisés dans des queues.

Par exemple : emails, notifications et video_processing

Chaque queue peut limiter le nombre de jobs exécutés en même temps.

emails → 10 jobs simultanés
video_processing → 2 jobs

### Job

Un job est une tâche enregistrée dans la base.

Il contient la queue, le worker, les arguments, son état et ses options.

Tous les jobs sont stockés dans la table `oban_jobs`

### Worker

Un worker est le module qui exécute le job.

```elixir
defmodule MyApp.OnboardWorker do
  use Oban.Worker

  def perform(%{args: %{"user_id" => user_id}}) do
    user_id
    |> MyApp.fetch_user()
    |> MyApp.onboard_user()
  end
end
```

Le worker reçoit les arguments et contient la logique métier.

### Etat et cycle de vie

Un job passe par plusieurs états :

- `ìnserted` à la création du job
- `scheduled` si le job est prévu plus tard
- `executing` quand le worker est en train de travailler sur ce job
- `retryable` après un échec
- `completed` quand le traitement a réussi
- `discarded` quand le job a échoué trop de fois

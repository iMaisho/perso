# Prioristation des jobs avec Oban

## Objectifs

Dans cet exercice nous allons apprendre :

- insérer **plusieurs jobs en une fois**
- gérer la **priorité des jobs**
- traiter un **backfill de données existantes**
- tester les jobs avec **Oban.Testing**

## 1 — Worker d’analyse de sentiment

Les utilisateurs laissent des **reviews** après leurs commandes.

Nous voulons analyser automatiquement leur sentiment pour savoir si les avis sont positifs ou négatifs.

Chaque job recevra :

- l'**id d'une review**
- récupérera la review
- analysera le sentiment.

### Implémentation du worker

```elixir
defmodule MyApp.SentimentAnalyzer do
  use Oban.Worker, queue: :analysis

  @impl Worker
  def perform(%{args: %{"id" => review_id}}) do
    review_id
    |> MyApp.get_review()
    |> MyApp.analyze_sentiment()
  end
end
```

### Fonctionnement

1. Le job reçoit les arguments (`args`)
2. On récupère la review avec :

```elixir
MyApp.get_review(review_id)
```

3. On lance l'analyse :

```elixir
MyApp.analyze_sentiment(review)
```

## 2 — Backfill des reviews existantes

Les nouvelles reviews seront analysées automatiquement.

Mais il existe **beaucoup d'anciennes reviews sans analyse**.

Nous devons créer une fonction qui :

1. récupère les reviews **sans sentiment**
2. crée un job pour chacune
3. les insère **en une seule opération**

### Implémentation

```elixir
defmodule MyApp.Analysis do
  import Ecto.Query

  def enqueue_backfill do
    MyApp.Review
    |> select([r], r.id)
    |> where([r], is_nil(r.sentiment))
    |> MyApp.Repo.all()
    |> Enum.map(&MyApp.SentimentAnalyzer.new(%{id: &1}))
    |> Oban.insert_all()
  end
end
```

`Oban.insert_all()` est **beaucoup plus performant** que `Oban.insert()` appelé dans une boucle.

## 3 — Test du backfill

Nous devons vérifier que seules les **reviews non analysées** génèrent un job

```elixir
ExUnit.start(auto_run: false)

defmodule MyApp.AnalyzerTest do
  use MyApp.ObanCase

  test "enqueue jobs only for unprocessed reviews" do
    %{id: id_1} = insert(:review, :unprocessed)
    %{id: id_2} = insert(:review, :unprocessed)
    %{id: id_3} = insert(:review, :unprocessed)
    %{id: _id_} = insert(:review, :analyzed)

    MyApp.Analysis.enqueue_backfill()

    review_ids =
      [worker: MyApp.SentimentAnalyzer]
      |> all_enqueued()
      |> Enum.map(& &1.args["id"])
      |> Enum.sort()

    assert [id_1, id_2, id_3] == review_ids
  end
end

ExUnit.run()
```

## 4 — Modifier la priorité des jobs

Par défaut, les jobs Oban ont `priority = 0` et sont exécutés selon `scheduled_at`, puis`id`

Plus le nombre est grand, plus la priorité est faible.

Le backfill peut contenir **des milliers de jobs**, mais si on ne change pas la priorité, les nouvelles reviews devront attendre que le backfill ait été résolu.

Nous voulons que les nouvelles reviews passent en priorité sur les anciennes.

```elixir
def enqueue_backfill do
  MyApp.Review
  |> select([r], r.id)
  |> where([r], is_nil(r.sentiment))
  |> MyApp.Repo.all()
  |> Enum.map(&MyApp.SentimentAnalyzer.new(%{id: &1}, priority: 3))
  |> Oban.insert_all()
end
```

## 5 — Test de la priorité

```elixir
ExUnit.start(auto_run: false)

defmodule MyApp.BackfillPriorityTest do
  use MyApp.ObanCase

  test "backfill jobs have a lower priority" do
    insert(:review, :unprocessed)

    MyApp.Analysis.enqueue_backfill()

    assert_enqueued(
      worker: MyApp.SentimentAnalyzer,
      priority: 3
    )
  end
end

ExUnit.run()
```
